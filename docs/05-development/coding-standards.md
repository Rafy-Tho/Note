# Coding Standards

- Validate external input on the server.
- Never trust client-provided ownership or user identifiers.
- Keep functions and modules focused.
- Use consistent naming and formatting.
- Use versioned migrations and transactions for related changes.
- Add unit, API, integration, component, end-to-end, and security tests according to feature risk.
- Link implementation work to requirements and acceptance criteria.
- Do not mark a feature complete with failing required checks or unresolved critical security and data-loss issues.
