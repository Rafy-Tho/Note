# Database Design

## Purpose

This document defines the MVP data model, relationships, ownership rules, constraints, and required indexes for PostgreSQL.

## Design Decisions

- PostgreSQL is the source of truth.
- IDs use UUIDs generated by the application or database.
- Timestamps are stored in UTC.
- Every private resource has an owning user.
- Permanent note deletion removes the note from normal application storage.
- Database details must not be exposed to the frontend.

## Entity Overview

```text
User
 |-- Notes
 |-- Notebooks
 |-- Tags
       |
Note --+-- NoteTags -- Tag
 |
 +-- Notebook
```

## Core Entities

### users

| Field | Rule |
| --- | --- |
| id | Primary key. |
| email | Required and unique after normalization. |
| password_hash | Nullable for external-provider accounts; plaintext passwords are never stored. |
| email_verified_at | Null until the email is verified. |
| created_at | Required UTC timestamp. |
| updated_at | Updated when account data changes. |

Profile fields are outside the MVP.

### sessions

| Field | Rule |
| --- | --- |
| id | Primary key. |
| user_id | Required foreign key to users. |
| token_hash | Required and unique; raw tokens are never stored. |
| created_at | Required UTC timestamp. |
| last_used_at | Updated for valid authenticated requests. |
| expires_at | Required session expiry timestamp. |
| revoked_at | Set when the session is invalidated. |

### auth_identities

| Field | Rule |
| --- | --- |
| id | Primary key. |
| user_id | Required foreign key to users. |
| provider | Required value: `google` or `facebook`. |
| provider_subject | Required stable identifier supplied by the provider. |
| created_at | Required UTC timestamp. |
| updated_at | Updated when identity metadata changes. |

The pair `(provider, provider_subject)` is unique. Provider email is not the identity key and is not used for automatic account merging.

### email_verification_tokens

| Field | Rule |
| --- | --- |
| id | Primary key. |
| user_id | Required foreign key to users. |
| token_hash | Required and unique; raw tokens are never stored. |
| expires_at | Required expiry timestamp. |
| consumed_at | Set after successful verification. |
| created_at | Required UTC timestamp. |

Only an unexpired, unconsumed token can verify an account.

### password_reset_tokens

| Field | Rule |
| --- | --- |
| id | Primary key. |
| user_id | Required foreign key to users. |
| token_hash | Required and unique; raw tokens are never stored. |
| expires_at | Required expiry timestamp. |
| consumed_at | Set after a successful password reset. |
| attempt_count | Tracks bounded validation attempts. |
| created_at | Required UTC timestamp. |

Only an unexpired, unconsumed token below the attempt limit can reset a password. Reset consumption, password replacement, and session revocation are one transaction.

### notes

| Field | Rule |
| --- | --- |
| id | Primary key. |
| user_id | Required foreign key to users. |
| notebook_id | Nullable foreign key to notebooks. |
| title | Required value; empty text is allowed. |
| content_json | Rich-text document; empty document is allowed. |
| searchable_text | Derived plain text used for search. |
| state | `active`, `archived`, or `trashed`. |
| restore_state | Previous state while the note is Trashed. |
| is_favorite | Boolean favorite flag. |
| revision | Incremented after each successful content update. |
| created_at | Required UTC timestamp; immutable. |
| updated_at | Updated after successful persistence. |
| trashed_at | Set when the note enters Trash. |

`restore_state` and `notebook_id` preserve the previous organization. If the notebook no longer exists, restoration uses Active with no notebook.

### notebooks

| Field | Rule |
| --- | --- |
| id | Primary key. |
| user_id | Required foreign key to users. |
| name | Required normalized name, unique per user. |
| created_at | Required UTC timestamp. |
| updated_at | Updated when the name changes. |

Deleting a notebook sets related notes to `notebook_id = NULL`; it does not delete notes.

### tags

| Field | Rule |
| --- | --- |
| id | Primary key. |
| user_id | Required foreign key to users. |
| name | Display name. |
| normalized_name | Required value used for uniqueness. |
| created_at | Required UTC timestamp. |

The pair `(user_id, normalized_name)` must be unique.

### note_tags

| Field | Rule |
| --- | --- |
| note_id | Foreign key to notes. |
| tag_id | Foreign key to tags. |

The pair `(note_id, tag_id)` is the primary key and prevents duplicate associations.

## Relationships and Delete Rules

| Relationship | Rule |
| --- | --- |
| User -> Notes | Every note belongs to one user. |
| User -> Notebooks | Every notebook belongs to one user. |
| User -> Tags | Every tag belongs to one user. |
| Note -> Notebook | A note may have no notebook; notebook deletion sets this value to null. |
| Note <-> Tag | Many-to-many through `note_tags`. |
| Note deletion | Removing a note also removes its tag associations. |
| Notebook deletion | Unassigns notes without deleting them. |

Application queries must verify ownership of both sides of every relationship. For example, moving a note requires ownership of the note and target notebook.

## Note-State Rules

```text
active <-> archived
  |
  v
trashed -> permanently removed
```

- Only Active notes can be archived.
- Only Archived notes can be unarchived.
- Active and Archived notes can move to Trash.
- Trashed notes are excluded from normal lists and search.
- Trashed notes remain until manual permanent deletion.
- Restore uses `restore_state` and the existing notebook when possible.

## Search Data

`searchable_text` is derived from the note title, rich-text text, and associated tag names when the note or tags change.

Search queries must filter by:

```text
user_id = authenticated_user_id
state IN (active, archived)
```

The Search design will define the PostgreSQL search index and ranking behavior.

## Constraints and Transactions

- Foreign keys prevent orphaned notes, notebooks, tags, and associations.
- Unique constraints prevent duplicate emails, notebook names, and tag names per user.
- State transitions must be validated by the application layer.
- Notebook deletion and note unassignment must be atomic.
- Tag assignment and removal must be atomic.
- Autosave updates must protect against stale revisions.
- Content updates must compare and increment `revision` atomically.
- Permanent deletion must remove note associations in the same transaction.

## Required Indexes

At minimum, provide indexes for:

- `users.email`
- `auth_identities(provider, provider_subject)`
- `email_verification_tokens.token_hash`
- `email_verification_tokens(user_id, expires_at)`
- `password_reset_tokens.token_hash`
- `password_reset_tokens(user_id, expires_at)`
- `notes(user_id, state, updated_at)`
- `notes(user_id, notebook_id, state)`
- `notes(user_id, is_favorite, state)`
- `notes(user_id, trashed_at)`
- `notebooks(user_id, normalized_name)`
- `tags(user_id, normalized_name)`
- `note_tags(tag_id, note_id)`
- The search document used by the Search design
